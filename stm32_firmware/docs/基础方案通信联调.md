# 基础方案通信联调操作

更新：2026-10-18。单通道台架已完成本轮实物检查，详见[板级验收记录与上位机接入清单](基础方案板级验收记录.md)。当前使用“通信联调_时序诊断”FS及bench HEX；原通信联调FS保留用于对照。ATK-MO8008保持H5直插；控制线见[H6连接表](../../FPGA_firmware/基础方案/通信联调/连接表.md)。本版不用于KY_AD9767双通道模块。

最新CH340端口为COM3，以实际枚举为准；脚本默认仍是COM4，下面命令请显式指定端口。若PowerShell拦截脚本，在项目根使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\stm32_firmware\tools\run_bench.ps1" -Port COM3 -ProbeOnly
```

## 1. 接线及下载

1. 两板断电，按连接表接7根控制线和GND。各自供电，不互接5 V。
2. Gowin打开`FPGA_firmware/基础方案/通信联调_时序诊断/g1_dac_spi.gprj`。中文路径打不开时，在该目录执行`scripts/open_project.ps1`，使用打印的英文盘符路径。
3. Programmer选GW2A-18C，FS选择时序诊断目录的`impl/pnr/g1_dac_spi.fs`。SRAM Program只用于临时下载，断电不保留。持久化使用External Flash Mode → `exFlash Erase,Program,Verify thru GAO-Bridge`，Generic Flash，地址0x000000，下载时钟2.5 MHz。成功依据为`Program and Verify flash successfully.`；Finished单独不代表成功。断电后只读Device Codes确认工作程序User Code为0x0000743C，再执行ProbeOnly和输出复测。不要选择旧的`g1_dac_stage1.fs`或原通信联调FS。
4. STM32通过ST-Link烧录`stm32_firmware/build-bench/nucsignal_f405.hex`。默认`build-gcc`不是此次联调版本。也可在项目根执行：

```powershell
.\stm32_firmware\tools\flash.ps1 -Profile bench
```

5. FPGA配置完成后复位STM32。STM32板载CH340/USART1的USB串口连接PC，115200 8N1。示波器仍接DA_OUT。上电时为基线码16，不会自动输出脉冲。

STM32在启动时对FPGA RESET_N产生低脉冲，然后probe并STOP。若FPGA晚于MCU配置，可用下面的脚本恢复，不必重刷固件。G1停止键F10按下会复位通信参数，需要重新COMMIT。

## 2. 只测握手

关闭占用同一个串口的图形上位机/串口助手。在项目根PowerShell执行，2026-10-18最新确认STM32端口为COM3；若以后变化，使用-Port指定CH340实际端口：

```powershell
.\stm32_firmware\tools\run_bench.ps1 -Port COM3 -ProbeOnly
```

通过条件：HELLO为F405-B2.0.0、channels=1、bench=true；RECOVER成功；STATUS为IDLE、fpga=true、error=OK。HELLO可能先报告缓存的FPGA-OFFLINE，最终以RECOVER与后续STATUS为准；恢复失败仍不通过。脚本退出前再次STOP并关闭串口。连续执行数次检查结果一致；单次成功不等于板间通信已充分稳定。

若FPGA:NO/恢复失败：核对新FS与新HEX是否匹配，再查READY、RESET_N及CS/SCK/MOSI/MISO；先用探头看SCK空闲低、READY高和RESET_N高。不要改成10.5 MHz去排错。

## 3. 四组输出测试

默认每次输出10秒，脚本每约250 ms发送状态请求；结束或Ctrl+C后尝试STOP。默认基线16，脉冲为负向输出。

```powershell
# A：原联调参数。示波器200 us/div测周期，再5 us/div看指数形状。
.\stm32_firmware\tools\run_bench.ps1 -Port COM3

# B：只改周期：1 kHz -> 500 Hz。
.\stm32_firmware\tools\run_bench.ps1 -Port COM3 -PeriodUs 2000

# C：只改幅度码差：224 -> 112。相对基线的脉冲幅度约减半。
.\stm32_firmware\tools\run_bench.ps1 -Port COM3 -AmplitudeCode 112

# D：只改衰减时间：12 -> 24 us，半幅恢复时间约加倍。
.\stm32_firmware\tools\run_bench.ps1 -Port COM3 -TauUs 24
```

每次顺序为HELLO→RECOVER/STOP→SET_PARAM→COMMIT→START→状态轮询→STOP。COMMIT包含FPGA生效参数及generation回读；START/STOP包含运行标志回读。参数范围：基线和码差0～255且两者之和≤255，周期128～10000 μs，τ1～100 μs，周期≥5τ。只支持CH1周期单指数。输出幅度用相对基线值测量；尚未支持准确的伏特设定。

第一组默认码差224预计与旧测试约5.48 V接近，取决于电位器、倍率及负载。新固件采用Q8.16递推指数，原固件为64点查表，尾部处理不同。对照周期、幅度及恢复形状，不要求两个码流逐点完全相同。

图形上位机当前可能发送伏特参数、双通道或数据上传，本版会拒绝未实现功能。首次使用本工具完成整条PC→STM32→FPGA→DAC链路验证；图形界面适配另行进行。

## 4. 停止与故障测试

- 每次脚本结束，确认屏幕显示停止状态、DA_OUT保持基线，无重复脉冲。
- 运行中按STM32 PA0停止键，确认停止；脚本检测到设备离开RUN后退出。
- 运行中按G1 F10，确认输出回基线，MCU发现generation不匹配并报错；下一次脚本恢复并重新提交。
- 强制结束PC进程且STM32仍供电，MCU约2 s无有效PC请求后尝试停止并报TRANSFER。
- 验证FPGA自主超时可在停止后将SCK线断开再启动失败，或由调试器暂停STM32时观察运行输出在约250 ms内停止。断线测试须避免探头/线头碰到电源脚；恢复接线后重新RECOVER、COMMIT。

屏幕/协议报告停止仅是数字状态证据，仍需示波器确认模拟输出；若控制通信完全中断，等待FPGA自身250 ms看门狗回基线。

## 5. 构建与证据

项目根执行：

```powershell
.\stm32_firmware\tools\build_bench.ps1
.\stm32_firmware\tools\test_bench.ps1
& '.\FPGA_firmware\基础方案\通信联调_时序诊断\scripts\build.ps1'
& '.\FPGA_firmware\基础方案\通信联调_时序诊断\scripts\simulate.ps1'
```

STM32应用代码以-Wall/-Wextra/-Werror编译，第三方旧库仍有已有警告；链接newlib无操作系统I/O桩函数警告不等于串口传输失败。默认Release与通信联调配置均复核编译。测试报告在`stm32_firmware/reports`及FPGA通信目录`reports`；测试临时目录自动清理。

桌面配置显式启用DEVELOPMENT_BYPASS_SAFETY_INPUTS=1，仅绕过未安装的A/B/PG检测；STATUS以null和safety_bypass=true表达未验证，不作为实际在位/供电检测通过。默认Release仍关闭旁路。TFT显示BENCH及CH2 unavailable。

每组保存示波器照片、当次参数和终端输出；完成以上硬件测试后才能把通信联调版标为实物通过。
